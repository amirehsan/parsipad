# Replace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Replace button on Polish and translation results that writes the generated text over the text the user selected in a site's own input, textarea or rich editor, with Undo; and the selection toolbar appearing in those fields so the button can be reached.

**Architecture:** Two new pure modules carry the logic: `content/editable-target.js` decides whether a selection is replaceable and captures where it is, and `shared/replace-text.js` writes text into that place through the browser's editing path and undoes it. `content/main.js` keeps one `currentReplaceTarget` from the toolbar or context menu to the box, renders Replace only when it is set, and reports through the existing toast. The popup reuses `shared/replace-text.js` on its own textarea.

**Tech Stack:** Plain ES modules, Manifest V3, shadow-DOM UI in the content script, Vitest with happy-dom, esbuild for Chrome and Firefox.

**Spec:** `docs/superpowers/specs/2026-10-28-replace-design.md`

## Global Constraints

- Both browsers from the same source. Inside an input or textarea, field text comes from `value`, `selectionStart` and `selectionEnd`, never from the Selection object (empty in Firefox).
- Every user-visible string lives in `lib/i18n.js` in both languages; Persian non-joiners are written as `‌` escapes. `tests/i18n-keys.test.js` fails on a key missing from one language.
- The label is "Replace", sentence case. No shortcut hint on the button. No confirmation dialog. No greyed-out Replace: when it cannot work it is not rendered.
- No new permissions in `manifest.json`. No em dashes or emoji anywhere.
- Toolbar never appears in password or other non-text inputs, read-only or disabled fields, selects, or opaque custom elements (hyphenated tag without a reachable shadow root).
- Branch: `fix/persian-orthography-prompts`, which already holds an unreleased 3.9.1 bump; this feature turns that release into 3.10.0 (Task 7).
- Commit messages: conventional prefixes as in `git log`; never mention Claude Code or add a Co-Authored-By line.

## Review Focus

1. A drag that runs past the word into trailing spaces or a newline: the replacement must cover only the trimmed text, leaving the user's whitespace (Task 1 tests `shrinks offsets to the trimmed text`).
2. A site that re-mounts its textarea (React) between selecting and clicking Replace: the stale element is detached, Replace must copy instead and say so (Task 2 `fails on a detached element`, Task 4 toast test).
3. The user types in the field after a replacement, then presses Undo: Undo must not overwrite the new typing; it does nothing when the inserted text is no longer at its offsets (Task 2 `undo refuses when the inserted text moved`).
4. Regenerate changes a version after the box opened: Replace must insert the text now on the card, not the first response (Task 4 `replaces with the regenerated text`).
5. A result with no translation (unsupported language, error card): no Replace, since there is nothing to insert (Task 4 `no Replace without a translation`).
